fathom-agent {{ .Chart.AppVersion }} installed into namespace {{ include "fathom-agent.namespace" . }}.

{{ if eq .Values.service.type "NodePort" -}}
Reach it from your workstation on any node's IP -- no port-forward needed:

  NODE=$(kubectl get nodes -o jsonpath='{.items[0].status.addresses[?(@.type=="InternalIP")].address}')
  export FATHOM=http://$NODE:{{ .Values.service.nodePort | default "<assigned-nodeport>" }}

{{- end }}
{{ else -}}
The Service is {{ .Values.service.type }}, so tunnel to it first:

  kubectl -n {{ include "fathom-agent.namespace" . }} port-forward svc/{{ include "fathom-agent.fullname" . }} 8081:{{ .Values.service.port }}
  export FATHOM=http://localhost:8081
{{ end }}
Ask it something:

  curl -s $FATHOM/chat -H 'content-type: application/json' \
    -d '{"question":"which pods are not running?"}'

The two endpoints it depends on:

  MCP     {{ .Values.mcp.url }}
  Ollama  {{ .Values.ollama.url }}  (model: {{ .Values.ollama.model }})

Check both at once -- /readyz is 200 only when Ollama answered AND the MCP server
advertised its tools. A 503 names which one failed:

  curl -s $FATHOM/readyz

{{ if .Values.ollama.service.create -}}
The Ollama Service is an ExternalName alias for {{ .Values.ollama.service.externalName | quote }}.
That name must resolve FROM INSIDE THE CLUSTER, which is not the same as resolving
on your workstation. If /readyz reports Ollama unreachable, check that first:

  kubectl run dnstest --rm -it --restart=Never --image=busybox \
    -- nslookup {{ .Values.ollama.service.externalName }}

If it does not resolve, skip the Service and dial the host directly:

  helm upgrade {{ .Release.Name }} ./helm \
    --set ollama.service.create=false \
    --set ollama.url=http://<host-ip-on-the-node-network>:11434
{{- else -}}
The Ollama ExternalName Service is disabled, so {{ .Values.ollama.url }} must be
reachable from a pod on its own.
{{- end }}

This release grants the agent NO Kubernetes permissions -- all cluster access goes
through fathom-mcp's ServiceAccount, and the pod mounts no token. This should print
nothing but a warning:

  kubectl auth can-i --list \
    --as=system:serviceaccount:{{ include "fathom-agent.namespace" . }}:{{ include "fathom-agent.serviceAccountName" . }}
